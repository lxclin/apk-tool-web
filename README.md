# APK Tool 1.4

面向安卓适配流程的 ADB 工具箱，包含桌面 GUI、FastAPI Web 控制台、本地 ADB WebSocket 代理，以及 Google Sheets / Asana 同步脚本。

完整迭代索引：[APK Tool 迭代总结](ITERATION_SUMMARY.md)（含历史记录和截至 10 月 13 日的更新索引）。

## 自动适配异常诊断

自动适配会在 `automation_reports/YYYY-MM-DD/` 为每次执行保存 JSON 报告。诊断最近 7 天：

```bash
python3 automation_diagnostics.py --days 7
```

也可以在桌面工具的自动化适配页点击“查看近7天异常”；添加 `--json` 可从命令行输出结构化结果。诊断识别复检后字段未变化、早期暂不适配或待复检结论被后续成功覆盖、超过 15 分钟无新事件的运行中报告，以及单次执行回放轮次过多。每条线索给出包名和本地报告路径；结果只代表自动执行历史，人工处理和 Asana 后续评论需另行核对。诊断摘要不输出广告 ID、af_key 或完整 Logcat。

聚合回放成功后会先强制停止当前检测应用，并确认主进程及子进程退出，再标记适配成功。清理未确认时任务进入“进程清理待确认”，批量队列暂停。

桌面标题和 `GET /api/version` 会明确显示版本及 `source/packaged` 运行方式，便于区分源码启动与旧打包应用。发布前运行 `python3 release_check.py`，确认版本清单、MAX Share 接收器和桌面/Web 打包入口完整。

敏感凭证不写入源代码：Asana PAT 和后台固定 Token 可在工具界面填写，也可分别通过 `ASANA_PAT`、`CP_ADAPT_TOKEN` 环境变量提供；Google Service Account JSON 路径使用 `APK_TOOL_SA_FILE`。请勿把凭证文件或 Token 提交到 Git。

## 功能清单

### 桌面版

入口：`python3 main.py`

- APK 工具页
  - 生成 Google Play 链接二维码。
  - 解析 URL，并自动回填包名、AppId、GP 链接。
  - 安装本地 APK、XAPK、拆分 APK 目录。
  - 从直链下载 APK/XAPK 并自动安装。
  - 在手机上打开 Google Play / market 页面。
  - APKCombo 下载。
  - APKPure 包名搜索安装。
  - 选择 APK、选择目录、设置 ADB 路径。
  - 第三方包清理，支持预览、白名单保留、一键卸载，以及逐包卸载进度和失败统计。
  - 记忆上次使用的路径和清理白名单。

- 页面预检页
  - 应用内购等加黑结论独立于后台提交结果：后台无记录或提交失败只保留后台异常，不解锁包体下载或二次检测。单项检查、批量预检、下载重试和自动适配执行前均检查加黑业务状态；断点保存该状态，旧队列还会核对当前已读取任务的加黑结论。
  - Google Play 优先下载；不可用或安装失败后，默认按 Aptoide → APKPure → APKCombo 自动兜底（G99 直接进入第三方策略）。也可切换为“仅 Aptoide”“仅 APKPure”或“仅 APKCombo”，各页面共享并记忆选择。历史下载失败任务继续使用所选策略重试，全部失败保留“第三方下载待确认”，记录每个来源的原因，不提前判“全网无包”。Aptoide 暂只接受 appupdater 的 TRUSTED 包体，按当前设备查询并下载主包和全部拆分包，安装前校验大小、MD5、ZIP、真实包名、CPU 和签名一致性。需要 Android SDK apksigner 和 Java；校验工具缺失则跳过 Aptoide，继续下一个来源。
  - “重试下载并适配”会重新读取今日未完成的下载异常任务，使用所选策略下载安装，验收和启动检查后仅将本批合格任务交给自动适配。APKPure 安装前核验文件包名（APK 需要 aapt/aapt2，XAPK 可读取 manifest.json）；支持停止，用户停止后不切换下一下载来源。两个网站的手动打开按钮仍可直接打开各自搜索页。
  - 页面预检、下载、手动打开 Google Play 页面及自动适配前检查连接设备的 Clash VPN：未连接时自动尝试启动，确认 VPN 已连接后继续。未安装、首次授权待确认、其他 VPN 占用或连接超时会停止本轮，不写入包体失败结论；首次 VPN 授权需在手机手动确认。
  - 聚合类型、广告 ID 和聚合 SDK Key 均无线索时，若 Google Play 公开下载量下限低于 18 万，统一回填“疑似白包，暂不适配”；`Native` 应用也先核验下载量，不因应用类型跳过此判断。后台清空适配参数并提交同一备注，Asana 与 Sheet 写入同一结论，跳过广告回放。18 万及以上或下载量未知不按此规则判白包。
  - “重置为待处理”按钮在确认后，将今日列表中仍为“自动化失败、待人工检查、待处理、第三方下载待确认”的未完成任务恢复为“待处理”。写入前重新读取状态，写入 Asana `RECHECK_REQUESTED` 评论、保留历史记录并清除阶段状态；成功、其他归因、暂不适配、加黑及其他失败类别不会重置。需启用 Asana 写入权限，预检或适配运行中不可操作。重置后手动点击“批量预检并自动适配”，使用届时连接的设备重新执行。
  - 未发现广告或应用内购标识的包继续下载安装，启动成功后自动适配，不自动加黑；G99 恢复队列同时接纳“启动失败”任务并重新下载安装。
  - 非游戏空参数结论（聚合类型为空或聚合 ID 为空）刷新后保留为终态，不重复自动适配。闪退判定按目标进程的 Java 致命栈、Native tombstone 或明确点名目标包的崩溃事件分别核验，排除相邻系统/检测组件异常；证据摘要保留包名和致命标记。
  - “读取今日任务”会同步读取任务评论，按最新有效评论恢复已加黑、暂不适配、闪退、参数待确认、后台提交失败、回放失败和聚合适配成功等状态；刷新不会再统一重置为待处理。
  - 评论已有终态业务结论的任务不会再次进入批量预检；“待人工检查”属于未解决状态，刷新后会恢复为“待处理”并重新入队。
  - 只读取与当天日期一致的 Asana 区段，例如 `7.30执行`，并保持任务顺序。
  - 从任务描述提取包名、UP2 AppId 和 Google Play 链接。
  - 可按顺序批量预检今日未完成任务，自动跳过已完成任务，并支持停止。
  - 支持“批量预检并自动适配”：完成页面检查、下载及启动检查后，将本轮合格且已安装的包体按列表顺序移交自动化适配队列。
  - 记录当日已读取 Task GID；一天内再次读取时只把真正新增的任务标记为“新增待预检”，避免重复处理旧任务。
  - 通过 ADB 在手机 Play Store 打开应用页面，不自动下载安装。
  - 读取 Android UI 控件文字，识别包含广告、仅应用内购、设备不支持和地区不支持。
  - 优先判断业务终止规则：仅标注应用内购且无广告时加黑；包名含独立 `jp` 段且页面存在明显日文内容时按日本包体加黑；未发现广告和内购标识的应用继续下载并人工确认。
  - UI 信息不足时可使用本机 Tesseract 对内存截图进行 OCR，不保留正常截图。
  - 页面信息未稳定时返回“暂时无法判断”，避免错误加黑。
  - 对仅内购、无广告/内购、设备不支持、地区不支持和无法判断结果写入幂等 Asana 评论。
  - 可选“检测到广告后自动下载安装”，通过 UI 控件定位安装按钮并等待包管理器确认完成。
  - 自动下载默认开启；默认单轮最多新下载 6 个、安装间隔 60 秒，页面全部预检后会继续补下载延后任务，遇到登录/验证或下载失败后暂停后续自动下载。
  - 大包在 Google Play 后台下载时不会阻塞后续任务；再次读取任务或开始批处理前会按设备安装状态把“后台下载中”自动刷新为“安装完成”。
  - 普通设备的自动适配优先执行 Google Play 页面预检及下载安装，包括“第三方下载待确认”的历史任务；预检加黑或页面信息不足时停止下载。G99 保留直接第三方下载的特殊路由。“仅 APKCombo / 仅 APKPure”控制第三方兜底来源，不跳过普通设备的 Google Play。
  - Google Play 因地区、设备或无包而无法下载时，按当前第三方下载策略获取替代包体。默认先检查并下载 APKCombo，失败后尝试 APKPure；只选 APKPure 时不会访问 APKCombo。下载未成功保留待确认，避免在兜底完成前写入“全网无包”。
  - 安装完成或检测到应用已安装后，可自动启动并观察进程与 Java/Native 崩溃日志（默认 20 秒）。
  - 确认闪退时评论“包体闪退，暂不适配”；无闪退时强制停止当前应用，再处理下一条任务。
- 自动化适配页（聚合适配后半程）
  - 与原有手动“一键复制全部”“跳转后台”和 ADB 操作按钮相互独立，不改变旧按钮逻辑。
  - 可从页面预检选中的 Asana 任务带入 Task GID、包名、UP2 appid 和原描述。
  - 聚合参数检测持续轮询 `最终判断`，正常至少等待 60 秒；日志仍在增长时最长等待 90 秒，避免在设备约 45 秒输出综合结果前提前判空。
  - 已取得 SDK Key 或聚合 ID、但始终没有综合结果时标记“检测结果未完整输出”，不误报为“聚合类型为空”。
  - 参数结果显示识别方式、识别依据、置信度和自动提交策略：AutoDetector 明确结论且无平台冲突时为高置信度；`video/inter` 固定文本不再作为广告位或推断依据；证据冲突、参数不完整时禁止提交并复检。
  - 自动将聚合参数写到 Asana 描述的 GP 链接下方，并保留包名、UP2 appid 与 GP 链接。
  - 自动化适配使用 `s10_package_info` 接口提交聚合参数，复用“数据同步”页的接口地址、X-Token、固定 token 和适配人员；依次校验写入响应、调用 `delete_a2_package_cache` 清除当前包缓存，再通过 `cp_adapt/list` 回读该包并逐字段比对。三个步骤均成功才进入广告回放。原有手动跳转后台逻辑保持不变。
  - `cp_adapt/list` 即使收到包名筛选条件也可能返回超过单页上限的完整列表；回读会逐页查找精确包名并核对字段。分页重复、缺页或超过安全扫描上限时中止回放，不把未完整读取误判为参数已生效。
  - 自动化 Logcat 读取限制单次返回量并带 ADB 状态检查和自动重试；设备在线时的瞬时读取超时会继续等待，持续的 ADB/Logcat 基础设施故障会安全停止批量队列且不会写入 Asana 业务失败结论。
  - 参数识别为空或广告 ID 缺失时，Asana 评论会列明缺失项、原始判断、SDK 名称、两类广告 ID 是否识别及归因线索；不会写出 SDK Key，也不会据弱线索自动猜测聚合类型。
  - 后台提交成功后强制停止并重启游戏，清除旧 logcat 后按应用 UID 监听聚合广告回放。
  - 每次重启成功后重新计算进程启动宽限，默认等待 25 秒；同时检查主进程、包名前缀子进程和前台 Activity。只有进程曾成功运行后再消失才判定异常退出，明确闪退仍要求 Java/Native 崩溃证据。
  - 后台提交期间收到停止请求时，当前接口提交、清缓存和回读校验原子步骤结束后立即终止，不再进入聚合回放。
  - 回放监听默认最长 300 秒，可在 10-600 秒范围内配置；只验证已配置 ID 的广告类型，两种 ID 都存在时必须分别回放成功；同一广告类型的临时失败最多重试 1 次。
  - 已确认聚合类型的包体在监听超时且未观察到目标广告请求时，标记为“广告未触发待验证”；观察到目标请求但未展示时，批量任务延后复测一次，仍无真实展示则标记为“广告展示待验证”，保留已校验参数，不据此否定聚合识别。临时推断的聚合类型若未验证成功，会撤销临时后台参数、保留真实检测证据并转人工复检，不直接判“暂不适配”。
  - 用户主动停止、设备体检失败、回放 Logcat 提前结束或注入兼容异常不会写成包体适配失败；Logcat 中断会停止批量队列并保留断点。
  - 批量断点保留所有未完成任务（包括前序延迟重试），恢复时先处理上次中断的任务，再处理其余未完成项；启动时会将已退出进程遗留的运行中报告标记为中断待复核。
  - 回放 Logcat 由独立读取线程持续批量排空，避免 AppLovin 等 SDK 的高流量初始化日志堵塞管道；判定器处理完整 UID 日志，界面仅显示匹配当前广告 ID 的展示、收益、状态和错误证据。
  - `loadAd`、`showAd`、`onAdLoaded` 和 `display_start` 不算成功；仅接受匹配广告 ID 的 `onAdDisplayed`、`onAdImpression`、`display_success` 或收益回调。
  - 回放超时会把每类广告的已展示与未验证证据写入 Asana 评论并标记待复检；真实运行错误按对应故障类别处理。
  - 聚合回放成功后写入结构化 Asana 成功评论，供页面预检刷新和当日总结恢复成功状态。
  - 首次按 IronSource 提交后，回放仍持续监听同一 UID 的 AutoDetector；若随后完整、高置信度识别为 MAX 或 LevelPlay，则清理工具此前提交的临时参数、重新校验提交并回放。普通 SDK 初始化日志不能单独触发切换。
  - 自动识别并关闭 Android 通知权限弹窗，避免弹窗遮挡游戏启动流程和广告触发。

- ADB 指令页
  - 读取和写入 `config.json`。
  - 推送 config 到 `/data/local/tmp/zygotehole/`。
  - 执行 `zygote_build.sh`。
  - 修复 `zygotehole` 权限。
  - 获取应用 UID。
  - 清除缓存、强制停止、打开应用、清空 Play Store 缓存。
  - 实时监听 logcat，支持按 UID 过滤。
  - 查看 Java 崩溃和 Native 崩溃日志。
  - 从 `ZGSDK.AutoDetector` 日志提取 `af_key`、聚合平台、聚合 ID、归因平台和各 SDK Key。
  - Adjust 归因且识别为 AppLovin/MAX 时，若检测完成后仍未取得 AppLovin SDK Key，标记“AppLovin SDK Key为空，暂不适配”，保留已识别字段与结论，不提交聚合参数、不执行回放；刷新列表和断点续跑同样遵守此规则。
  - 生成适配后台 URL。
  - 一键复制全部提取字段。
  - 显示 ADB 控制台输出，并支持停止当前命令。

- 自动化脚本页
  - 粘贴 JSON 后批量规范化 `delay`。
  - 首个 `delay` 至少 15000ms，后续按配置最小值调整。
  - 复制结果、清空脚本。

- 数据同步页
  - 从 CP 后台拉取适配记录并写入 Google Sheets。
  - Google Sheets 到 Asana 的幂等同步。
  - 创建或更新 Asana 任务，并回填任务链接。
  - 记忆同步相关凭证和路径。
  - 支持粘贴 Asana 任务地址后自动解析并保存父任务 GID，避免把链接中的 story/comment GID 当成任务 GID。
  - 每次同步按目标执行日期自动查找匹配的周父表，不沿用旧父任务 GID；父表缺失、重复或查询失败时停止。联合同步在写入 Sheet 前完成父表检查。

- 当日总结页
  - 读取指定日期执行区段的任务评论，汇总聚合成功、动作成功、暂不适配和加黑结果。
  - 对归因问题、聚合类型或广告 ID 缺失、回放失败、闪退、全网无包、设备/地区限制、Google 登录和人工备注等原因分别计数。
  - 同时识别“动作适配成功”“动作适配完成”等人工评论表达，并优化包名与原因之间的换行和可读性。

### Web 版

入口：`python3 main_web.py`

- 启动 FastAPI 服务，并自动打开 `http://localhost:8000`。
- 提供 REST 接口：
  - `GET /api/config`
  - `POST /api/config`
  - `GET /api/device`
  - `POST /api/get-uid`
  - `POST /api/adb-path`
  - `GET /api/whitelist`
  - `POST /api/whitelist`
  - `POST /api/upload-apk`
- 提供 WebSocket `/ws`
  - 推送 Config、执行 `zygote_build`、获取 UID、清缓存、强制停止、打开应用。
  - 打开 URL、安装文件、APKCombo、APKPure。
  - 实时 logcat 监听。
- 已同步桌面版“页面预检”页：
  - 读取当天 Asana 区段，保持任务顺序并自动跳过已完成任务。
  - Asana PAT 由用户在页面输入，只保留在当前页面内存，不写入浏览器存储。
  - 单条或批量执行 Google Play 页面预检，复用桌面版广告优先判断逻辑。
  - 自动为仅内购、无广告、设备/地区不支持、无法判断等结果写入幂等 Asana 评论。
  - 自动下载安装默认开启，默认单轮下载上限为 6，支持下载冷却间隔和预检结束后的补下载。
  - 安装完成后可启动应用检查闪退，检查结束自动杀死应用进程。
- 已同步“自动化适配”页的聚合参数回填、识别证据与置信度、后台接口提交/清缓存/回读校验和广告回放检测能力。
- 前端位于 `static/index.html`。
- 支持 IP 白名单控制。

### 本地代理

入口：`python3 adb_proxy.py`

- 默认监听 `ws://localhost:9527`。
- 提供本机 ADB 能力给远端页面或静态页面调用。
- 共享页面预检、自动安装、启动闪退检查与 `ZGSDK.AutoDetector` 解析逻辑，保证桌面版和 Web 版一致。
- 提供 `POST /fill` 和 `GET /fill/latest`，GUI 会轮询 `http://localhost:9528/fill/latest` 自动回填数据。
- 打包后会自动查找可用 ADB。

### 数据同步脚本

入口：`python3 -m auto_asana.main`

- 拉取 CP 适配记录。
- 写入 Google Sheets。
- 创建、更新和回填 Asana 任务链接。
- 保持幂等同步。

## 打包

项目保留了三个 PyInstaller 目标：

- `APK Tool.spec`：桌面版。
- `APK Tool Web.spec`：Web 版。
- `ADB Proxy.spec`：本地代理。

桌面版另提供两个互不覆盖的独立发行包：

- `APK Tool Standard.spec`：标准版，构建时强制关闭五项内部功能，已安装授权也不能开启。
- `APK Tool Internal.spec`：内部版，保留签名授权机制；在所有者已授权设备上启用内部功能。

一键构建并分别生成 `.app` 与 `.zip`：

```bash
./build_editions.sh
```

```bash
pyinstaller "APK Tool.spec"
pyinstaller "APK Tool Web.spec"
pyinstaller "ADB Proxy.spec"
```

`build_proxy.sh` 可用于构建带 adb 的 macOS 代理 `.app` 和 `.dmg`。

### TradPlus 聚合适配（2026-10-13）

TradPlus 纳入正常聚合提取与适配，不再按“TradPlus暂不适配”处理。提取 APP ID、SDK 版本及所属广告位；明确的聚合判断、支持的归因、所需归因 Key、初始 Activity 和有效广告位满足现有校验后，经接口提交、清缓存和后台回读确认，再等待真实广告回放。APP ID 与版本保留在结果/任务描述中，不冒充 AppLovin SDK Key；无广告位或证据不足时不提交。历史“TradPlus暂不适配”任务仍需重置为待处理后重新检查。

### 后台数据保护与选中任务重试（2026-10-13）

- 正常提交与自动终态清理前，先读取精确包名的现有记录并保存本地快照（`backend_submission_history/`，不含认证令牌）。读取或快照失败即停止写入。快照记录写入前值、提交值及回读确认值，保留人工恢复依据。
- 人工备注原样保留；仅清除有已验证工具写入记录或明确操作授权的旧工具备注。未知来源的“暂不适配”文字不会自动认领。自动终态备注追加到人工备注后，不覆盖人工内容。
- 已有 Block 原因时停止自动写入；缺少后台已有的有效广告位、AF Key、AppLovin SDK Key 时停止覆盖并提示缺失字段。引导 Activity 没有新检测来源时保留旧值。
- 已获用户明确授权的历史工具备注可单独登记：检测通过并正常提交时清除，不提前修改后台。
- 页面预检列表支持多选；选择重试起点后点击“仅重试选中任务”。支持页面预检与下载、重新检测并适配、从参数提交继续、仅重新回放。刷新、后台安装续接及断点恢复都保留选中范围。
- 从提交/回放继续要求该任务最近一次保存的参数完整且置信度高；仅回放先只读核对后台参数，不重新下载、提交参数或轮换广告位。存在未完成断点时先恢复或放弃该断点，不覆盖队列。

当前后台没有版本条件写入接口，读取旧值与写入之间无法做到跨客户端原子比较；同一包适配期间应避免在其他客户端同时编辑。当前改动提供提交前快照和提交后核验，没有实现自动回滚按钮。

### 重置为待处理的范围（2026-10-13）

重置按钮只处理今天列表中选中的可重试任务；不选中时不执行，不再扫描并重置整张列表。可重试状态包含闪退、启动失败、回放失败、参数缺失、第三方下载待确认及历史 TradPlus 暂不适配。服务端执行前重新读取最新评论；读取失败、任务已完成/已加黑或状态已变为不可重试结论时跳过并报告。重置仅新增复检评论，保留历史，不修改后台参数、备注或自动启动队列。

### IronSource / LevelPlay 广告位优先级（2026-10-13）

同一广告类型同时出现具体广告位与 `inter/video` 时，只保留具体 ID；没有具体 ID 时仍允许 IronSource/LevelPlay 的合法符号值。解析、Asana 描述、手动后台链接、接口参数及回放候选采用同一规则。最终平台已明确时不从其他 SDK 区块借用 ID。回放期间 IronSource 的占位结果被完整、高置信度 LevelPlay/MAX 结果替代时，重建候选并通过标准提交流程回读验证，不复用旧占位候选。
